# 元数据规范 v3

> 目标：**一套结构，四种情况都能吃**——有图/无图、有稿/无稿、单集/系列、有卡司/无卡司。
> 核心思路：**资产显式声明 + 来源可追溯 + 校验可自动化**。

---

## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **资产即列表** | 音频、图片都是数组，每项自带路径和元信息。没有"隐含约定"（比如"图片就在文稿同目录"这种） |
| **来源必留痕** | 每个资产记录它从哪来、用什么规则匹配上的。出问题时能追溯，不用猜 |
| **校验写进数据** | 期望几张图、实际几张、有没有可疑，直接存在 meta 里。doctor 只读不猜 |
| **缺失是正常态** | 无图 = `"images": []`，无稿 = `"text": null`。不搞"字段不存在"的隐式语义 |
| **kind 显式** | 单集和系列是两种东西，用 `kind` 标出来，不靠 `parts` 是否存在来推断 |

---

## 2. 结构

```jsonc
{
  "schema": 3,
  "id": "2049-2016-0402",

  // 单集 = "single"（1 个音频）；系列 = "series"（N 个音频共享一份文稿）
  "kind": "single",

  "title": "数学三大危机",
  "date": "2016-05-02",
  "year": 2016,
  "duration_sec": 510,
  "series": null,          // 所属主题系列（【暗黑无界】这类），与 kind 无关

  "assets": {
    // 音频：数组。single 恒为 1 项，series 为 N 项
    "audio": [
      { "path": "audio.mp3", "duration_sec": 510, "gain_db": -1.2, "lufs": -17.2 }
    ],

    // 封面/波形：可为 null
    "cover": "cover.jpg",
    "thumb": "thumb.jpg",

    // 文稿：可为 null。有文稿才有 blocks
    "text": {
      "markdown": "transcript.md",
      "blocks": "blocks.json",
      "chars": 1844,
      "anchor_source": "ratio+silence"   // 将来可以是 "asr-align"
    },

    // 配图：数组，每项带 caption（来自源文件名）
    "images": [
      { "path": "images/01.png", "caption": "薛定谔" },
      { "path": "images/02.jpg", "caption": "毕达哥拉斯学派" }
    ]
  },

  "taxonomy": { /* domain/topics/content_type/humor/... 保持不变 */ },
  "derived":  { "sleep_friendly": true, "scene": ["睡前"] },

  // 每个资产的来源，出问题时用来回溯
  "provenance": {
    "audio":  { "from": "2016\\0502数学三大危机.mp3", "rule": "title-exact" },
    "doc":    { "from": "文字版全集\\2016\\短篇\\0502…\\0502….docx", "rule": "title-exact" },
    "images": { "from": "文字版全集\\2016\\短篇\\0502数学三大危机\\", "rule": "episode-folder" }
  },

  // 自动校验结果，doctor 直接读
  "validation": {
    "images_expected": 7,
    "images_found": 7,
    "warnings": []
  },

  "flags": { "has_transcript": true, "text_source": "doc", "needs_asr": false },
  "pipeline": { "version": "3.0.0", "built_at": "..." }
}
```

## 3. 图片归属规则（这次踩坑的地方）

```
doc_dir = dirname(provenance.doc.from)

if basename(doc_dir) in ("短篇", "长篇"):
    # 文稿直接躺在分类目录里 → 没有专属文件夹
    episode_dir = doc_dir / <去掉日期前缀的文稿名>   # 若存在
    rule = "category-sibling" 或 "none"
else:
    episode_dir = doc_dir
    rule = "episode-folder"

images = 递归收集 episode_dir 下的图片，按自然序排序
if len(images) > 120:
    # 可疑：几乎肯定是匹配到了上层目录
    images = []
    validation.warnings += "image_count_suspicious"
```

**上一版错就错在没有 `rule` 这个显式判定**，走了"取文稿父目录"的隐式逻辑，
碰到分类目录就炸成 599 张。

## 4. caption 从哪来

源图片的文件名本身就是图注（"美国物理学家恩里克·费米.jpg"）。
拷贝时改名成 `01.png` 会丢信息，所以：

- 拷贝时按**同一排序**配对，把源文件名（去扩展名）写进 `caption`
- 改名只改文件名，不改语义

---

## 5. 兼容性

- `schema: 3` 是硬版本号，App 见到非 3 就拒绝加载并提示
- 旧字段（`assets.audio` 是字符串、`assets.images` 是字符串数组）在 v3 里**全部改结构**，不做兼容分支——
  反正只有我们自己在读，一次改干净比长期背兼容包袱划算
- 磁盘缓存文件名带版本：`library.v3.cache`，升级时旧缓存自动失效，不会出现"改了 schema 但读旧缓存"的坑

---

## 6. 校验清单（doctor 自动跑）

| 检查 | 规则 |
|---|---|
| 音频存在 | `assets.audio[].path` 全部存在 |
| 时长对账 | 各段时长之和 ≈ `duration_sec`（±1%） |
| 文稿 | `text != null` 时两个文件都在，且 `chars` 与 blocks 字数差 < 5% |
| 配图 | `len(images) == validation.images_found`，且文件都在 |
| 配图可疑 | 单期 > 120 张 → warning |
| 系列 | `kind == "series"` 时 `len(audio) > 1` 且 `text` 不为空 |
| 单集 | `kind == "single"` 时 `len(audio) == 1` |

### caption 清洗规则

源文件名不全是图注，混着 `AlbumArt_{GUID}_Large`、`src=http...` 这类垃圾。清洗规则：

- 含 `albumart` / `folder` / `src=http` / `images_upload` / `_large` 等关键词
- 不含中文且长度 > 14（纯英文长串多半是系统文件名）
- 纯十六进制 GUID

命中就置空，图片保留、只是不显示图注。共清洗 66 期。

### 缓存版本

缓存文件名从 `library.cache` 改成 `library.v3.cache`。
schema 变了旧缓存自动失效，不会再出现"改了结构却读到旧缓存"的情况。
