## 7. 真机上踩的坑（都已修）

| 现象 | 原因 | 修法 |
|---|---|---|
| 显示"没有找到媒体库" | adb 推到 `Android/data/<pkg>/` 的文件属主是 `shell`，Android 17 的 FUSE 不让 App 读 | 库改放 `/sdcard/2049lib`，加 `MANAGE_EXTERNAL_STORAGE`，用 `appops` 授权 |

| 启动即崩 | 两条无日期节目的 id 都是 `2049-0000-0000`，LazyColumn key 重复 | 列表 key 改用 `dir.absolutePath`；管线 `make_id` 给无日期的加 hash |
| 标题被状态栏压住 | targetSdk 35 在 Android 15+ 强制 edge-to-edge | 根布局加 `safeDrawingPadding()` |

## 3.8 播放页手势：横滑换页，竖滑换图（2026-11-23）

### 冲突

画面页原来用横向 Pager 切图，和"横向滑动切换三种模式"直接打架——同一个手势两处都要用。

### 方案：把两个轴分开

| 轴 | 作用 | 范围 |
|---|---|---|
| **横向** | 切换 封面 / 画面 / 字幕 | 整页 |
| **纵向** | 内容自己的滚动 | 画面页换图、字幕页滚文本、封面页滚文字 |

实现上，三种模式本身变成一个 HorizontalPager（pageCount = 3），
画面页的图片 Pager 从 HorizontalPager 换成 VerticalPager。两个 Pager 不在同一轴上，不会抢手势。

### 为什么不是别的方案

- **点按左右边缘换图**：热区小，和"点击图片全屏"冲突，误触率高
- **缩略图条**：占空间，而且这一期动辄 10+ 张，条也滑不完
- **只在空白处横滑换页**：不可发现，用户根本不知道哪里算"空白"

纵向换图后，手感和抖音/小红书的图文流一致，而且底部加了一行"上下滑换图"提示。

### 验证

- 封面 →(左滑)→ 画面 →(左滑)→ 字幕，反向也通
- 画面页上下滑：1/14 → 2/14 → 3/14，图注跟着变（《流感》、三八线）
- 字幕页纵向滚动正常，不误触发翻页

## 3.9 字幕居中 + 滚动变丝滑（2026-11-23）

### 居中

之前三种写法都没对准，因为 scrollOffset 的单位/语义和 LazyColumn 的布局顺序容易混。
这次改成**按实测位置算距离**：

1. 从 layoutInfo.visibleItemsInfo 找到当前段的真实偏移和高度
2. delta = 段中心 - 视口中心
3. nimateScrollBy(delta)

不再猜符号，直接量。

### 丝滑

原来 scrollToItem（瞬移）改成动画后仍然只有约 160ms，观感还是"闪"。

现在按两种情况：

| 情况 | 做法 | 时长 |
|---|---|---|
| 目标段已在屏幕内（正常顺播） | nimateScrollBy(delta, tween(480, FastOutSlowInEasing)) | **480ms**，可控 |
| 跳转很远（拖进度条、点远处段落） | nimateScrollToItem 定位 + 320ms 校正 | ~300ms |

实测（30fps 录屏逐帧算像素差）：滚动过程从 1 帧突跳变成 **约 15 帧连续变化**（≈500ms），
而且差值曲线是 6.5→12→9→7→3.5→2.5 的先加速后减速，符合 ease-out。

### 顺带

当前段的文字颜色和字号也加了 	ween(320) 过渡，切换时不再是硬切。
"回到当前"胶囊逻辑不变。

## 3.10 配图全屏（2026-11-23）

### 为什么之前"没完全放大"

两个原因叠在一起：

1. Compose 的 Dialog **默认 usePlatformDefaultWidth = true**，窗口宽度会被限制成手机宽度的一个比例，
   所以弹层本身就是个居中的窄条；
2. 图片用的是 illMaxWidth()，只铺满那个窄条，高度按比例，看起来就更小。

### 改法

`kotlin
Dialog(
    onDismissRequest = onClose,
    properties = DialogProperties(usePlatformDefaultWidth = false, decorFitsSystemWindows = false)
) { ... }
`

- 图片 illMaxSize() + ContentScale.Fit：铺满屏幕、不变形、留黑边
- 双指缩放 1×–6×，带边界钳制（缩放后拖动不会把图拖飞）
- **单击退出**（detectTapGestures，双指缩放不会误触发）
- 缩放后底部提示「双指缩放 · 轻点退出」

### 验证

## 3.11 自然语言点播接入（2026-11-23）

把 Python 原型 `pipeline/retrieval.py` 移植进 App，逻辑一一对应：

| 阶段 | 实现 |
|---|---|
| 理解需求 | `INTENT_SYS` 提示词 → JSON 意图（topics/domain/tone/时长/难度…） |
| 检索节目 | 本地 BM25-lite（bigram + idf + 长度归一）+ 标签打分 + 主题命中，召回 40 条 |
| 排列候选 | `RERANK_SYS` 提示词，让模型从候选里挑一期并给理由 + 队列 + 置信度 |

### 设计上的几个决定

- **密钥不进代码**：`LlmConfig` 存 SharedPreferences，任何 OpenAI 兼容接口都能填
- **没有 Key 也能用**：直接本地召回，界面标「未配置 AI」
- **AI 失败不假装成功**：401/超时会在卡片上显示原文，然后退回本地结果
- **理解失败不致命**：意图解析挂了就退回纯关键词召回，不让整个流程崩

### 顺手加的能力

`am start --es q "今天想听火星"` 可以直接进点播页。以后做分享入口/桌面快捷方式能复用。

### 验证

- 本地路径：输入「今天想听火星」→ 选《天问一号》，候选是火星系列
- 失败路径：填一个假 Key → 卡片显示 `HTTP 401 Authentication Fails`，同时给本地结果
- 真实 LLM：**未验证**（这台机器没有可用 Key），逻辑与 Python 原型一致

### 踩的坑

`kotlin.math.log(x)` 需要 base 参数，Python 的 `math.log` 是自然对数——要用 `ln`。
编译期就报「No value passed for parameter 'base'」，比线上算错好。


## 3.12 修「设置页点了没反应」（2026-11-23）

用户反馈：填了真实 Key，点「测试连接」和「保存」都没反应。

### 排查

复现发现**功能其实是通的**——prefs 里有 Key，测试也回了「连接正常」。
问题在两处叠加：

1. 状态提示渲染在按钮**上方**。点「保存」后提示出现，把按钮整体下推约 100px，
   紧接着点「测试连接」就落在空白处了——**移动的按钮**。
2. 输入完 Key 后第一次点击往往只是收起键盘，被系统消费掉。
3. 反馈文字在按钮下方，键盘弹起时容易在可视区外。

### 修法

- 状态框移到按钮**下方**，按钮位置恒定
- 保存/测试都弹 `Toast`，不依赖屏幕位置
- 点击时主动收起键盘并 `clearFocus()`
- 容器加 `imePadding()`，键盘弹起时按钮不会被顶出屏幕

### 验证

连续点「保存」→「测试连接」，两次都生效（截图 `save2` / `test2`）。
真实 Key 跑通两种查询：

- `今天想听火星` → 《【摘下星星送给你】火星》，理由「专讲火星地貌与探测」
- `想听点轻松有趣的，十几分钟` → 《惊奇人体：重口味开车》，
  意图解析成「轻松 / 有趣≥4 / 10-20 分钟」

### 教训

**不要把会改变布局的提示插在按钮上方。** 用户连点两个按钮时，前一个操作改变了后一个的位置，
表现出来就是「点了没反应」——而且是那种最难查的「其实成功了，但下一次失败」。


## 3.13 结构化输出的四层保证（2026-11-23）

### 问题

换了推理模型后，点播直接失效：返回「AI 没能理解这句话」或「库内没有符合条件的节目」。

### 根因（三个叠加）

1. **`response_format: json_object` 只保证"是合法 JSON"，不保证字段对**
   DeepSeek 官方原话是 *guarantees the message the model generates is valid JSON*。
   官方公布的解析率：模型直出 78% → 85%，**再加应用侧正则才到 97%**。
   我之前没有"校验失败怎么办"的分支，失败就等于静默降级。
2. **推理模型会先花 token 思考**，`max_tokens=400` 被思考吃光，答案被截断成空 JSON。
3. **约束太严时召回为空**，直接告诉用户"没有"，没有放宽机制。

### 改法

| 层 | 之前 | 现在 |
|---|---|---|
| 语法 | `JSONObject(raw)` | `extractJson()` 抠出 JSON（兼容 ```json 包裹、前后解释） |
| 结构 | 无校验 | `validateIntent()` 逐字段收敛：枚举不在词表就丢弃、数值钳制到区间 |
| 取值 | 部分钳制 | 全部钳制 + 词表过滤（模型编的"轻松科普"这类假枚举会被丢掉） |
| 失败处理 | 直接降级 | **带错误原因重试一次**（把失败率从 ~15% 压到 ~2%） |
| 召回为空 | 报"没有" | **逐级放宽**：去睡前 → 去时长 → 去门槛，并告知"已放宽限制" |
| token | 400 / 500 | 1200 / 1600（给推理模型留思考空间） |

另外：把「模型返回空对象」和「用户只想按风格听」区分开——
`Intent.isEmpty` 为真才判定解析失败，否则空 topics 是合法情况。

### 验证

`睡前听，不想动脑`（deepseek-v4-pro，推理模型）：

> 已为你找到 →《好好睡一觉比什么都重要》7 分钟
> 理由「专门讲睡眠，助眠且不费脑」，意图解析出「动脑≤2」

### 模型的取舍

同一个查询：

- `deepseek-v4-pro`：结果更贴切，但**两次调用约 60–90 秒**
- `deepseek-flash`：约 5–10 秒，质量也不错

默认给 flash，追求质量可在设置里换。**换模型要重新测一遍**，因为不同模型的 JSON 遵从度差别很大。


## 3.14 用户数据搬到媒体库（2026-11-23）

### 问题

卸载重装后收听记录、进度、收藏全丢。数据在应用私有目录（`/data/data/<pkg>/files`），
卸载即删——这是 Android 的设计，不是 bug。

### 方案对比

| 方案 | 重装后 | 换手机 | 问题 |
|---|---|---|---|
| 应用私有目录 | ❌ | ❌ | 就是原问题 |
| Android 自动备份 | ✅（有 GMS 时） | ✅ | 国产 ROM 常无 GMS；25MB 上限；不可见 |
| **媒体库 `state/` 目录** | ✅ | ✅ | 数据和内容混放 |

选第三条，原因：这个 App 的媒体库本来就在 `/sdcard/2049lib`，用户会自己推送/迁移它，
数据跟着库走最符合实际使用方式。同时保留自动备份作为兜底。

### 实现

```
/sdcard/2049lib/state/
├── listens.jsonl    收听流水（原来在私有目录，首次启动自动迁移）
└── profile.json     进度、上次播放、收藏的镜像
```

- `State.dir()`：优先媒体库 `state/`，**写探针文件**确认可写，否则回退私有目录
- `State.listensFile()`：发现新位置没有、旧位置有，就复制过来（无损迁移）
- `Profile.restore()`：启动时若 prefs 为空且磁盘有镜像，则恢复
- `Profile.dump()`：每 60 秒 + 退出时落盘
- **API Key 不写入镜像**（`ai_` 前缀全部排除）——媒体库目录是明文可见的，密钥不能落在那儿

### 验证

真机走了一遍完整流程：

1. 装新版 → `state/listens.jsonl`（583 B，从私有目录迁移）+ `state/profile.json` 生成
2. `adb uninstall` → `state/` 目录仍在
3. 重新安装 → prefs 自动恢复 `last=2049-2020-0119`、`pos_…=13674`
4. 首页显示「已听 5 分钟」、我的显示「今天听了 5 分钟」

### 代价

**重装后 API Key 需要重填**。这是刻意的：密钥不该出现在共享存储里。
如果嫌麻烦，后续可以接 `EncryptedSharedPreferences` + 手动导出，但仍然不会走媒体库。


## 3.15 播放队列（2026-11-23）

### 做法

- **队列只存节目 id**，播放单位仍是"一期"（多段节目内部由 Media3 连播）
- 一期放完由 App 监听 `Player.STATE_ENDED` 推进到下一期，而不是把整队列塞进 Media3 的 playlist
  —— 理由是每期的分段结构不同，塞进一个 playlist 后段边界和进度计算会很乱
- 队列和索引存 prefs（`q_ids` / `q_idx`），会跟着 `Profile.dump` 一起镜像到媒体库 `state/`，重启、重装都不丢

### 入口

| 位置 | 行为 |
|---|---|
| 搜索结果「播放」 | 用 `pick + queue` 填满队列并从头播（队列来自 LLM 精排的 queue 字段） |
| 节目详情「加入队列」 | 追加一期 |
| 播放器「下一期」 | 播队列下一项，到底就停 |
| 我的 → 播放队列 | 看整个队列：当前项高亮、点任意项跳播、单项删除、清空 |

### 验证

真机走的完整链路：

1. 搜「火星」→ 点播放 → `q_ids` 写入 6 期、`q_idx=0`
2. 播放器点「下一期」→ `q_idx` 0→1，`last` 变成第 2 期
3. 把进度拖到末尾等它播完 → **自动** `q_idx` 1→2（自动续播生效）
4. 进我的 → 播放队列：显示「6 期 · 正在播第 3 期」，第 3 项高亮
5. `force-stop` 重启 → `q_idx=2`、队列 6 期仍在，且已镜像到 `state/profile.json`

### 踩的坑

`uiautomator dump` 在播放页一直报 `could not get idle state`——播放器进度每秒刷新，界面永远「不空闲」，
拿不到控件坐标。后来改成截图裁剪 + 按像素找控件位置，才发现自己一直在用**缩放后的预览图坐标**去点，
实际坐标差了 600px。**坐标必须从 UI 树或原图取，不能看缩略图估。**


## 3.16 队列入口改到播放器 + 上一期（2026-11-23）

### 为什么要改

队列放在「我的」不合理：它只在"正在播"时有意义，离开播放器去翻菜单才能看到下一期，太绕。
而且播放器右上角那个按钮本来是死的（原来接的是空实现）。

### 改成

- **右上角按钮** → 弹出队列底部抽屉（Spotify / Apple Music 的标准位置）
- **「我的」里的队列入口删掉**，避免两个入口
- 抽屉里：当前项高亮、点任意项跳播、单项删除、清空

### 控制条改成 5 键

`上一期 / 回退15秒 / 播放 / 前进30秒 / 下一期`

按播客类 App 的通用布局（Pocket Casts 同款）。顺带补上了原本缺的**前进 30 秒**——跳片头有用。

### 配图轮播

| | 之前 | 现在 |
|---|---|---|
| 间隔 | 4 秒 | **7 秒** |
| 过渡 | 默认弹簧（瞬间吸附） | **650ms tween + FastOutSlowInEasing** |
| 图片加载 | 直接换 | **280ms 淡入**（Coil crossfade） |

录屏 4fps 抽帧测：换图间隔从 4 秒变成实测约 6–7 秒（录屏期间我点过播放，效应重启过一次）。

### 踩的坑

**播放页是提前 `return` 的分支**，我把队列抽屉写在了它后面，导致抽屉永远不渲染。
把抽屉放进 `if (playerOpen)` 分支内部才生效。

这跟之前"搜索页在详情页前面 return"是同一类错误：**Compose 里用 early return 做路由时，后加的覆盖层一定要放在对应分支内部**，不能放在所有分支之后。


## 3.17 四个手感修复（2026-11-23）

### 1. 进度条打开时在起点

**根因**：播放页打开的那一刻，Media3 里还没加载这一期，`currentPosition` 只能是 0。
进度条读的是播放器位置，所以显示 0；点了播放才 `seekTo` 到上次位置。

**修法**：进入播放页时先 `prepare()` 并定位到上次位置（**不自动播**）。
`PlayerBox` 拆出 `loadEpisode(ep, startMs, autoPlay)`，`playEpisode` 变成它的特例。

验证：打开播放页未点播放，进度条显示 `5:57 / 11:51`。

### 2. 队首/队尾提示

上一期在队首、下一期在队尾时弹 Toast：「已经是第一期了」「已经是最后一期了」。
之前是静默无反应，用户会以为按钮坏了。

### 3. 回退/前进改 10 秒

原来 15 秒回退 + 30 秒前进，不对称也不精准。统一成 10 秒，图标换成 `Replay10` / `Forward10`。

### 4. 放大配图暂停轮播

**第一次改完没生效**：`paused` 传进了 `ImagePane`，但 `LaunchedEffect(auto, playing, ep.id)` 的 **key 里没有 `paused`**——
Compose 的 effect 只在 key 变化时重启，而这里的轮播是一个 `while(true)` 循环，
key 不变 → 循环继续跑 → 放大期间照样翻页。

加上 key 才真正生效。实测：1/19 →（放大 11 秒）→ 1/19；关闭后 9 秒 → 2/19。

### 教训

**`LaunchedEffect` 里读到的参数，必须全部进 key。** 这和之前"轮播卡半页"（key 里多了 `currentPage`）是同一类 bug 的两种形态：
- key 里放了会变的变量 → 协程被反复取消
- key 里漏了会变的变量 → 循环看到的是旧值，改不动

判断标准很简单：**这个 effect 依赖哪些值来改变行为，key 里就必须有哪些值。**


## 3.18 情景模式（2026-11-23）

### 先回答一个前置问题：要不要先做响度均衡？

**已经有了。** 每期的 `gain_db` 是构建期用 `ebur128` 测的，播放时按它设音量。

但这次发现一个隐患：音量有**两个地方**在写——每期的增益、睡眠定时的渐弱。
换一期就会把渐弱覆盖掉。所以先把音量收口成一个 `Volume` 对象：

```
实际音量 = 每期增益 × min(定时渐弱, 情景渐弱)
```

三处写入互不覆盖，也不会互相打架。

### 六个模式

| 模式 | 目标时长 | 筛选 | 淡出 |
|---|---|---|---|
| 睡前 🛌 | 20 分钟 | sleep_friendly、load≤2、平静/怀旧/好奇 | **最后 8 分钟淡到静音** |
| 通勤 🚇 | 25 分钟 | 历史叙事/人物传记/时事评论，有故事线 | 无 |
| 家务 🧹 | 20 分钟 | 轻松/好奇，趣味≥4 | 无 |
| 专注 🎧 | 40 分钟 | 杂谈/科普，load≤3，低刺激 | 无 |
| 运动 🏃 | 20 分钟 | 热血/紧张/震撼 | 无 |
| 小酌 🍷 | 30 分钟 | 怀旧/平静/沉痛，长节目 | 无 |

规则全在本地，**不调 LLM**——点一下就要出声，不能等 5 秒。

选片逻辑：按时长/情绪/负荷/类型过滤 → 打分 → 贪心凑到目标时长（最多 4 期，主题重复≥2 个就跳过）。

### 淡出怎么算

每秒算一次"队列剩余时长"（从当前期到队尾的总和减去当前进度），
在最后 `fade` 分钟里 `音量 = 剩余 / fade时长`，播完自动暂停并提示。

实测日志：

```
remain=1320s vol=1.0     ← 刚开始，不在淡出窗口
remain=614s  vol=1.0     ← 还在窗口外
remain=264s  vol=0.552   ← 264/480 = 0.55
remain=260s  vol=0.544
remain=1s    vol=0.004   ← 几乎静音后才暂停
```

### 各模式的候选量（真实库上算的）

睡前 112 期 / 通勤 133 / 家务 1377 / 专注 188 / 运动 197 / 小酌 167。
睡前那 112 期是**严格筛选**后的量，够用。

### 踩的坑

- `BuildConfig` 在 AGP 8 里默认不生成，要 `buildFeatures { buildConfig = true }`
- 又是坐标：我拿缩略图估的位置点情景卡片，实际差了 400 多像素，点了三次都没反应

## 3.20 修编辑页返回键 + 改用滑块（2026-11-23）

### 1. 系统返回键在编辑页失效

**根因**：`BackHandler` 的 `when` 分支里没有 `sceneEdit`。
编辑页是"提前 return"渲染的，按返回时走的是 `minePage -> null`，
但 `sceneEdit` 还非空，界面纹丝不动——看起来就是"返回键没反应"。

修法：`BackHandler` 的 enabled 条件和分支都加上 `sceneEdit`，
顺序是 播放器 → 详情 → **编辑页** → 设置页 → 搜索页 → 底栏。

> 这已经是同一类问题的第三次：**每加一个覆盖层，就必须同步 BackHandler 和渲染顺序**。

### 2. 数字类偏好改成滑块

| 项 | 之前 | 现在 |
|---|---|---|
| 单篇时长 | 下限/上限两排 chips（12 个） | **一个 RangeSlider**（5–60） |
| 一段多长 | 7 个 chips | Slider（10–120，步长 5） |
| 听哪几年的 | 4 个预设（不限/近3/近5/近8年） | **RangeSlider（2016–2026，按年）**，拉满=不限 |

趣味度/动脑/门槛仍是 chips——1–5 的滑块比 chips 难点，还更占高度。

年份从"只有下限"升级成 **`yearMin` + `yearMax`** 双端，能选"2018–2022"这种区间。

### 3. 顺手修了一个存在很久的崩溃

logcat 里反复出现：

```
IllegalArgumentException: Service not registered:
  MediaControllerImplBase$SessionServiceConnection
```

**原因**：`PlayerBox.release()` 没有防重入，退出时释放两次。
**修法**：加 `released` 标志 + `onDispose` 里 `runCatching { box.release() }`。

这个崩溃一直在，只是发生在退出时，不影响使用，所以没被发现。

### 坑

`defaults()` 原来用位置参数，加了 `yearMax` 字段后整个错位（类型对不上，编译期就报错）。
改成本具名参数，以后加字段不会再错。


## 3.21 情景模式去重、系列关系、睡眠重构、段落检索（2026-11-25）

这一轮全部来自实际使用反馈。

### 1. 情景模式「来回就那几个」

**表象**：每次点睡前，出来的节目高度重复。

**根因**：`remember()` 只存「上一次选中的那几期」，而 `pick()` 里补时长的循环
根本没读这个记录——第一期换了，后面几期永远一样。

**修法**：
- 历史从「上一组」改成「最近 120 期」，滚动淘汰
- 第一期改成**按分数加权随机**（原来是前 40 名洗牌，高分项仍然扎堆）
- 补充循环也过滤历史，实在没新的才回退

**验证**：连续三次点睡前，队列两两重合 0 期。

### 2. 系列节目没有关联

数据里其实没有任何「系列」关系——「普京传（6）」只是标题里带个编号。

**修法**：
- 新增 `detect_collections.py`，按标题里的「（N）」「（上/中/下）」识别，≥3 期才算
- 识别出 35 个系列、257 期，写进 `meta.collection = {name, seq, size}`
- 详情页显示「系列 · 普京传 第 6 期 / 共 27 期」+「按顺序听」
- 情景模式选到系列节目时，能整条放下就整条，放不下就从第一期开始

### 3. 睡眠模式重构

旧逻辑：队列剩余时间不足 N 分钟时线性淡出 → 必须选短的节目。

新逻辑（按用户实际体验设计）：
- 从**开始后第 15 分钟**起淡出，10 分钟内到 0
- 到 0 后 5 分钟无操作 → 暂停
- 按**音量键**（息屏时用系统音量变化兜底）→ 恢复音量、重新计时

配套：`ScenePrefs` 新增 `fadeStartMin` / `fadeLenMin` / `idleStopMin`，
旧偏好用 `scene_ver` 自动迁移。

### 4. 段落级检索

搜索命中从「整期」细化到「第几段、第几分几秒」。

实现上没做全局倒排索引（1268 万字，手机上不划算），而是在候选期的
`blocks.json` 里扫：中文取二元组、英文取整词，整串出现直接加 10 分，
命中词数够门槛才算，点击直接跳到那一段播放。

### 5. 其它

- 设置页移除「播放速度 / 跳过片头」（用户明确不用）
- 滑块和选项加触感反馈
- 详情页系列卡片

### 踩坑

- `playSegment` 里用到 `startPlay`，Kotlin 局部变量有声明顺序要求，必须放在其后
- `JSONArray` 没有 `optJSONArray(String)`，要先用 `JSONObject` 包一层


## 3.22 数据备份策略（2026-11-25）

**教训**：之前跑完 ASR 就删了服务器上的音频副本和本地暂存目录，虽然那些确实是可再生的，
但「加工结果只存在手机或服务器上」是不可接受的状态——手机丢了、服务器清了，打标和
时间轴就没了。

**现在的规则**：每跑完一批，自动做一次带日期的快照。

```
E:\2049备份\<日期>\
  library\shows\2049\...     meta.json + blocks.json + transcript.md
  asr\<批次>\*.json           ASR 原始转录
  _manifest.json               期数、文件数
  _checksums.json              每个文件的 SHA256，可校验完整性
```

工具：`tool/backup_library.py`（`--zip` 额外压一个包）。

**备份范围**只含不可再生的加工结果（约 95 MB），不含 47 GB 的音视频素材——
后者是原始数据，丢了可以从源头重新整理，加工结果丢了才是真的没了。


## 3.23 情景模式回归纯本地（2026-11-25）

试过让 LLM 参与挑片，实际效果反而更差——**同一场景反复给出同样的几期**，
而且要多等一次网络往返。用户决定：情景模式不用 LLM。

现在的规则：

- 只用**没听过**的节目（有收听记录，或进度超过 5 秒）
- 系列纯净：队列里出现系列就只放这一条系列（按顺序从第 1 期起），
  否则只放单集，不掺系列碎片
- 某条系列听过一半以上，整条不再出现
- 本地打分 + 前 80 名加权随机，保证每次不一样
- 听过的都筛完了才放宽到全部

LLM 只保留在「智能点播」（自然语言搜索）里，那里它确实有用。


## 3.24 系列识别重做（2026-11-25）

第一版只认「标题（N）」一种写法，漏掉了大量系列：【日本简史】…、化工简史：…、
科学狂人：…、苹果公司1976/1984、中国领先技术之X、释永信（第一回）、资治通鉴（序一）。

重做后的识别规则（按优先级）：

| 规则 | 例子 |
|---|---|
| 方括号 | 【日本简史】倭国大王 |
| 括号第N | 释永信（第一回）…… |
| 序字 | 资治通鉴（序一）…… |
| 括号编号 | 普京传（6）…… / 某期（上） |
| 第N回 | xxx 第3集 / 第2回 |
| 上中下 | xxx（上）（下） |
| 之字系列 | 中国领先技术之航空钛合金 |
| 冒号前缀 | 化工简史：吃饱穿暖 |
| 词干兜底 | 归一化后前 8 字相同 |

关键改动：
- **门槛从 ≥3 降到 ≥2**（化工简史、哺乳动物简史上/下 这类两期系列之前被刷掉）
- 归一化去掉括号、标点、数字、结尾中文序号 → 苹果公司1976 和 苹果公司1984 能并成一组
- 同名组合并（不管命中哪条规则）
- 规则顺序：具体标记优先，**冒号前缀放最后**（它最宽，放前面会抢走「释永信（第一回）」这类）

结果：**405 个系列 / 1423 期（44.2%）**，之前只有 44 个 / 257 期。


## 3.25 清理相册污染（2026-11-26）

**现象**：手机相册里混进两三万张封面和配图。

**原因**：媒体库放在公共目录 /sdcard/2049lib/，Android 的媒体扫描器把里面的
21,301 张配图 + 3,218 张封面全部收录，实测媒体库有 28,275 条记录指向该目录。

**处理**：
1. 目录里放 .nomedia（App 启动时也会自动创建），阻止后续收录
2. 用 content delete 按路径删除已有记录（只删索引，不动文件）
3. 结果：媒体库 32,565 → 7,563 条，指向 2049lib 的记录归零

**注意**：db shell content delete --where 的引号会被 PowerShell 和 adb 双重吃掉，
写进脚本文件推到 /data/local/tmp/ 再执行才可靠（见 	ool/del_media.sh）。
