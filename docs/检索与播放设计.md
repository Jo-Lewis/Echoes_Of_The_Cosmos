# 检索与播放设计

> 三件事：**怎么找到那一期**、**找到了怎么挑段落**、**播放列表怎么组**。

---

## 1. 三级检索

```
查询 ──► ① 意图画像 ──► ② 节目级召回 ──► ③ 段落级定位 ──► ④ LLM 精排
       (LLM-A 或规则)      (bigram+向量)      (候选内线性扫)      (LLM-B)
```

### ① 意图画像

在线走 LLM-A，离线走规则表（见 §6）：

```json
{
  "domain": ["天文"],
  "topics": ["火星"],
  "style_want": ["轻松"],
  "level_max": 2,
  "cognitive_max": 3,
  "duration_max": 1800,
  "needs_story": null,
  "exclude": ["硬核"],
  "must_have": "火星"
}
```

### ② 节目级召回

三路并集，各自归一到 0–1：

| 路 | 方法 | 权重 |
|---|---|---|
| 字面 | bigram 倒排，tf-idf | 0.35 |
| 语义 | 文章级向量余弦（3,038 × 512，全内存） | 0.35 |
| 标签 | 多维标签匹配度（见 §2） | 0.30 |

硬过滤先砍：`duration_max`、`standalone`、`exclude`、同系列配额（≤2）。

取 Top 40 进下一步。

### ③ 段落级定位

**这一步回答"某一期里某一段讲了火星"**。

在这 40 篇的约 700 个 chunk 内线性扫描：

```
chunk_score = 0.5 * 字面命中（bigram 重合 + 词密度）
            + 0.5 * 向量余弦
```

然后**聚合回文章级**——这是关键，否则"提了一句火星"会打平"讲了一整段火星"：

```
article_passage_score = 0.55 * max(chunk_score)          // 最强的一段有多强
                      + 0.25 * (命中段数 / 总段数)        // 覆盖度：是主营还是顺带
                      + 0.20 * 主题命中（topics 里有没有） // 是不是这篇的主旨
```

只有 `max(chunk_score)` 高而覆盖度低的，标记为"**顺带提到**"，不进首选，但在结果里展示：

```
这期 12:34 提到过火星（不是主题）
```

### ④ 精排

把 40 条候选（含每个的 2–3 个最强片段 + 起止时间）交给 LLM-B：

```json
{
  "pick": { "id": "2049-2017-0129", "start_ms": 754000, "reason": "整期讲火星，11 分钟" },
  "queue": [ {"id": "…", "why": "同系列"}, {"id": "…", "why": "更轻松"} ],
  "confidence": 0.86
}
```

`start_ms` 让"想听讲火星那段"直接从那一段开播，而不是从头。

**延迟预算**：①0.5s + ②10ms + ③30ms + ④1.5–2.5s ≈ **2.5–3.5 秒**。
优化：②③ 在用户打字/说话时就可以预跑（本地，不花钱），只等 ④。

## 2. 多维联合打分

标签不是布尔过滤，是**加权距离**。每期有一个维度向量，查询也有一个，算匹配度：

```
tag_match = Σ_d  w_d · sim_d(q_d, e_d)
```

| 维度 | 比较方式 | 默认权重 |
|---|---|---|
| `domain` | 集合交集 / 查询集合大小 | 0.20 |
| `topics` | 交集数 / max(1, 查询主题数) | 0.25 |
| `style` | 集合交集（有"轻松"命中轻松/幽默/故事化） | 0.20 |
| `level` | `1 - |q.level_max - e.level| / 3`，超上限直接 0 | 0.10 |
| `cognitive_load` | 同上 | 0.10 |
| `emotional_tone` | 交集 | 0.10 |
| `pace` | 相等 1，差一档 0.5 | 0.05 |

权重写在 `weights.json`，方便你调（"我发现它总给我推太硬的"→ 调高 `level` 权重或降低 `level_max`）。

**风格词的同义词映射**（本地 JSON，不花 API）：

```json
{
  "轻松": ["轻松", "幽默", "故事化", "杂谈漫聊"],
  "硬核": ["严肃硬核", "进阶"],
  "故事": ["故事化", "人物传记", "历史叙事"],
  "烧脑": ["进阶", "硬核"],
  "不费脑": ["入门", "杂谈漫聊"]
}
```

## 3. 播放模式

播放列表不再是一条固定产物，而是**可切换的队列构建策略**。切换时不打断当前播放，只重建后面。

| 模式 | 队列怎么来 | 适合 |
|---|---|---|
| **单集** | 只播选中的，播完停 | 想认真听完一期 |
| **系列连播** | 同 article 的下一段 → 同 series 的下一集 | 鲁迅 22 幕、早期长篇 |
| **主题深挖** | 同 topic，按 `level` 从浅到深 | "想系统了解火星" |
| **电台** | 以选中为种子，MMR 扩散，越往后越远 | 不想选，一直有得听 |
| **漂移** | 每期用上一期的向量续推，慢慢漂走 | 长时间背景音、做别的事 |
| **睡前** | 只选 `sleep_friendly`，总时长封顶，自动渐弱 | 睡前 |

实现上就是一个接口：

```kotlin
interface QueueBuilder {
    fun build(seed: Episode, intent: Intent, history: List<Play>, mode: Mode): List<Episode>
}
```

六种实现，几十行一个。

**参数化的细节**（这些决定体验好坏）：

- **队列总时长**优先于条数：默认凑 35–45 分钟（一次睡眠的量），而不是固定 8 条
- **MMR 去重**：`score = λ·相似度 - (1-λ)·与已选的最大相似度`，λ=0.7 起步
- **同系列配额**：同一 series 在队列里最多 2 条（"系列连播"模式除外）
- **不要连续撞车**：同 domain 不连续超过 3 条
- **已听过的降权**：7 天内听过的分数 ×0.6，跳过的 ×0.3

## 4. 睡眠友好设计

不是"加个定时器"，是一整套可以一起开关的"夜间模式"。

### 4.1 缓慢音量衰减（重点）

你说的"很缓慢的那种减弱"，正确做法是**从开始播就在缓慢下降**，而不是到点才淡出：

```
每 10 分钟 -1.5 dB（可配 0 / -1 / -1.5 / -2 / -3）
30 分钟累计 -4.5 dB
```

关键细节：**按感知响度（LUFS）衰减，不是按线性幅度**。线性降 6 dB 会让低频先消失，听着像"变薄、变远"，很出戏。做法是按等响曲线补偿低频，实际是：

```
gain(t) = -1.5 * (t / 600s)   // dB
apply_loudness_compensated_gain(gain)
```

实现上如果嫌复杂，退一步用「分 20 段的小台阶 + 每段 2 秒线性过渡」，人耳基本听不出台阶。

### 4.2 其余开关

| 功能 | 默认 | 说明 |
|---|---|---|
| 定时停止 | 30 分钟 | 15/30/45/60/听完这期/播完队列 |
| 末尾淡出 | 开 | 最后 60 秒额外降到 0 |
| **片头跳过** | 开（18 秒） | 每期固定开场白。可自动识别：前 40 秒与全库其他期开头相似度 > 0.8 → 判为片头 |
| **片尾跳过** | 开（12 秒） | 固定结束音乐 |
| 夜间音量上限 | 60% | 防误触把音量推到最大 |
| 语速缓降 | 关 | 1.0 → 0.92，可选 |
| 播完淡入环境音 | 关 | 雨声/风扇，避免突然静音惊醒 |
| 通知栏"+10 分钟" | 开 | 定时器在锁屏可见、可延长 |

### 4.3 刻意不做

- **入睡检测**：用加速度计判断"不动了"不准（翻身就误判），且隐私敏感
- **闹钟式停止**：突然安静会惊醒，一律走淡出

## 5. 离线模式

### 5.1 触发

启动检测 + 请求失败降级。UI 顶部一条明显的"离线模式"提示，**但功能不能阉割到不能用**。

### 5.2 查询理解改为规则

```python
# 本地规则表
RULES = [
  (r"轻松|有趣|不费脑|随便", {"style": ["轻松"], "level_max": 2, "cognitive_max": 3}),
  (r"短一点|短点|十分钟", {"duration_max": 900}),
  (r"硬核|深入|详细", {"level_min": 2, "duration_min": 1800}),
  (r"故事|人物", {"content_type": ["人物传记", "历史叙事"]}),
  (r"火星|黑洞|量子", ...)  # 主题词直接从 topics 词表里匹配
]
```

加上一个**主题词表**（从全库 `topics` 聚合出来，约 3,000 个词），用最长匹配抽主题。

### 5.3 两个降级策略

| 策略 | 行为 |
|---|---|
| **结果列表** | 离线时不自动播，直接给 Top 10 列表让用户点（因为规则匹配不确定性高） |
| **缓存命中** | 最近 30 次在线查询的结果缓存在本地，同样的说法直接复用（"随便来一期"这种高频说法基本都命中） |

### 5.4 胶囊按钮全部有本地实现

`随便来一期 / 轻松有趣 / 短一点 / 接着上次 / 按系列听` —— 这五个按钮离线时**必须全都可用**，因为它们覆盖了 80% 的真实使用。离线体验的好坏，基本由这五个胶囊决定。

## 6. 无文稿节目的鲁棒性

全库约 69 段音频没有文稿（0.2%），另有 63 篇文稿没有音频。**任何环节都不允许因为缺文本而失败或崩溃。**

| 环节 | 有文稿 | 无文稿 |
|---|---|---|
| 入库 | 正常 | 照常建目录、封面、音频，`has_transcript=false` |
| 打标 | 用全文（~3,000 token） | 用标题 + 系列上下文 + 相邻期做弱打标，`text_source=none` |
| 节目级召回 | bigram + 向量 | **只用标签、标题、时长、向量**（向量由标题+弱摘要生成） |
| 段落级定位 | 扫描 40 篇的 chunks | **跳过**，这一期只以整期身份参与 |
| 结果展示 | 可显示"12:34 提到火星" | 只显示节目卡，不显示段落命中 |
| 播放 | 正常 | 正常 |
| 阅读页 | 正文 + 滚动 | 「这一期暂无文字版」+ 一个「补转录」按钮 |
| 队列 | 正常 | 正常（不得因缺文稿被排除） |
| 同步 | 传 blocks.json | 不传，`manifest` 里标记 |

ASR 补齐后：`text_source` 改为 `asr`，重新生成 `blocks.json` 与 chunk 向量，`needs_asr=false`。**因为 `meta.json` 是唯一真源，这一步只是覆写字段，不动音频。**

## 7. 失败与降级矩阵

| 情况 | 行为 |
|---|---|
| 断网 | 离线模式：规则理解 + 列表展示 |
| LLM-A 超时 | 直接用规则画像，继续走 |
| LLM-B 超时 | 用本地综合分最高的作为 pick，其余按分排 |
| LLM-B 返回不存在的 id | 丢弃，降级本地 Top1 |
| 召回为空 | 放宽 `duration_max` 和 `level` 再试一次；仍空则随机一期 `sleep_friendly` |
| 段落定位全为 0 | 只给整期，不显示"第 X 分提到" |
| API 余额不足 | 提示 + 永久切离线模式 |

所有降级都要**在 UI 上明说**（"这次是本地帮你挑的"），否则用户会以为推荐质量变差了。
