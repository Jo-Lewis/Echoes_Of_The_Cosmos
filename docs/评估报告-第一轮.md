# 检索评估报告 · 第一轮

日期：2026-11-23
库：**3,150 期已打标**（3,218 期中除 64 期待转录、4 期打标失败）

---

## 1. 结论

**门槛通过。** 自动判定 19/19 全中，人工判定 13 条里 10 条可接受。
综合 Top-1 估计 **80–85%**，高于设定的 70%。

但"100%"这个数字要打折看——自动判据偏宽（见 §4），别当成真实准确率。

| 指标 | 结果 |
|---|---|
| 自动判定 | **19 / 19 = 100%** |
| 人工判定（我逐条看） | **10 / 13 可接受** |
| 单次延迟 | **1.5–2.7 秒** |
| 单次成本 | 约 ¥0.03（两次 flash 调用） |

## 2. 好的部分

**主题类查询几乎无失误。** 火星、黑洞、鲁迅、量子、癌症、咖啡、明朝、心理学，全部选中真正讲这个主题的那一期，且理由说得通。

几条典型：

| 查询 | 选中 | 评价 |
|---|---|---|
| 来一期轻松有趣的，大概十几分钟 | 《2025年搞笑诺贝尔奖》 | 完美 |
| 有没有讲心理学的，来一期长点的 | 《找寻真我：荣格的分析心理学》 | 完美 |
| 讲中国古代历史的 | 《中国古代常识》官制（上） | 好 |
| 想听点让人平静的 | 【秋之篇】白露 | 好（节气类确实是慢节奏） |
| 太累了，随便来点不用动脑的 | 《提高知屎水平：科学拉屎指南》 | 好，正是要这种 |
| 睡前听，别太刺激 | 【春之篇】立春 | 好 |

**"轻松有趣"这类情绪查询真的能work。** 这是当初最担心的一类——向量检索无能为力，靠标签却能稳稳命中。说明"多维度 + 固定词表 + 刻度值"这套设计是对的。

## 3. 弱的部分

### 3.1 "顺带提到"仍然会污染 topics

查"黑洞，要长的，能听一小时"，选中了《时间旅行：回到过去与未来》（53 分钟）——
它确实有一节讲黑洞，但主旨是时间旅行。

根因：打标时把"讲了 5 分钟的次要话题"也写进了 `topics`。
修法：打标时区分 `topics`（主旨）和 `mentions`（提及），召回时只认前者。

### 3.2 上下文查询完全没实现

"接着刚才那期往下听" → 选中了《资治通鉴（四）》。
因为查询里没有任何检索信号，模型只能瞎猜。

这一条**必须靠播放器状态**，不是检索层能解决的。App 里要用 `currentEpisode` 注入上下文。

### 3.3 模糊指代不稳

"有没有讲那个……就是那个天上的东西" → 《【最】圆》。勉强算对（天文），但纯属运气。

这类查询需要多轮澄清，第一版可以接受"给个大概相关的"。

### 3.4 4 期打标失败

| 原因 | 期数 | 处理 |
|---|---|---|
| 内容审核拦截（HTTP 400 Content Exists Risk） | 2（纳粹德国政治笑话、犹太人在德国） | 只按标题打弱标 |
| JSON 截断 | 1（泰坦之谜：地狱即天堂） | 重试 |
| 未知 | 1（天下江山第一楼） | 重试 |

## 4. 自动判据为什么偏宽

自动判分只检查"标题 / topics / 关键词里有没有命中词"，**不检查是不是主旨**。
所以《时间旅行》因为有 `黑洞` 这个 topic 就算命中，尽管它不是讲黑洞的。

真实准确率应该按"人看了觉得对不对"来算——13 条人工里 10 条可接受，
按这个比例倒推，自动的 19 条大概有 2–3 条是运气好。

**估计真实 Top-1 ≈ 80–85%。**

## 5. 下一步建议

| 优先级 | 事项 |
|---|---|
| P1 | 打标增加 `mentions` 字段，把"顺带提到"和"主旨"分开 |
| P1 | App 端把 `currentEpisode` 注入检索，解决"接着刚才" |
| P2 | 补 4 期失败的打标 |
| P2 | 加入收听历史，"没听过的"才可能达标 |
| P3 | 33 条里再补 10 条边界用例（跨主题、多人称、否定句） |

**结论：检索层可以进 App 了。** 剩下的问题都在"有状态"的部分，需要播放器配合。
