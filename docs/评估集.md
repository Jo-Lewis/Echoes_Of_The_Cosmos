# 检索评估集（草案，待确认）

> 用途：在对 3,154 期跑打标**之前**定好标准，打完对着跑一遍，得出命中率。
> 先定标准再打分，避免"事后挑标准"。
>
> 判定方式：`auto` 用标题/标签正则自动判；`human` 需要人听一下或看摘要判断。

---

## 1. 指标

| 指标 | 定义 | 门槛 |
|---|---|---|
| **Top-1 命中率** | 自动选中的那一期符合期望 | **≥ 70%** 才继续做 App |
| Top-5 命中率 | 期望结果出现在前 5 条候选 | ≥ 90% |
| 硬约束违反率 | 违反时长/排除项的比例 | ≤ 5% |
| 理由可用率 | LLM 给出的 `reason` 说得通 | ≥ 85% |

**Top-1 < 70% 就不写 App**，回去改摘要写法、标签词表、召回权重。那个迭代便宜 100 倍。

### G. 用户原话（4 条，权重最高）

这四条是真实会说的话，比前面 30 条更可信。**Top-1 命中率单独统计这一组。**

| # | 查询 | 期望 | 判定 |
|---|---|---|---|
| 31 | 来一期轻松有趣的，大概十几分钟 | `emotional_tone` 含 轻松，时长 10–20 分钟 | human |
| 32 | 有没有讲心理学的，来一期长点的 | `domain` 含 生物/医学/人文社科 且 topics 近"心理"；时长 ≥ 30 分钟 | human |
| 33 | 讲中国古代历史的 | `domain` = 历史，topics 含 朝代/古代 | auto（`历史|古代|唐|宋|明|清`） |
| 34 | 来一期小众的我还没听过的 | 非热门主题 + 未收听；**依赖播放历史，第一版只能人工判断** | human |

> 34 暴露了一个设计缺口：**"没听过"需要播放历史参与排序**。第一版至少要做「已听过的降权」和「跳过的不推」，否则这条永远不达标。

## 3. 自动判分怎么做

```python
def check(case, picked):
    if case["must"] and not re.search(case["must"], picked["title"] + " " + picked["summary"]):
        return "miss"
    if case["not"] and re.search(case["not"], picked["title"]):
        return "violation"
    if case["dur_max"] and picked["duration_sec"] > case["dur_max"]:
        return "violation"
    if case["dur_min"] and picked["duration_sec"] < case["dur_min"]:
        return "violation"
    return "hit"
```

`human` 用例由我人工过一遍，记录"可接受 / 不可接受 + 原因"。
