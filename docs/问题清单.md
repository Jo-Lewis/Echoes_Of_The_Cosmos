## BUG-001 返回后无法回到播放页，且进度丢失

**状态**：✅ 已修（2026-11-23）
**发现时间**：2026-11-23
**现象**：在播放页点返回（回到列表/首页），再点同一期想继续听 —— 界面进不去播放页，或者进去了但从头开始播，之前的进度没了。

### 根因（三处叠加）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `MainActivity.kt:103` `startPlay` | 无条件调用 `box.playEpisode(ep)`，而它内部是 `setMediaItems(items, 0, 0L)` —— **每次点都重建队列、位置归零** |
| 2 | `MainActivity.kt:122,128` | 导航只有 `screen` 一个字符串，返回是硬编码 `screen = "home"`，**没有返回栈**。从列表进去、返回却回到首页，用户只能重新点列表 |
| 3 | 全局 | 没有"当前正在播哪一期"的判断。即使 controller 还在播这一期，也照样重建队列 |

### 修法

```kotlin
val currentId = box.controller?.currentMediaItem?.mediaId      // "id#partIndex"
val same = currentId != null && currentId.substringBefore('#') == ep.id

if (same) {
    screen = "player"          // 只切界面，不动播放器
} else {
    box.playEpisode(ep, resumeMs(ep.id))   // 从上次位置续播
    screen = "player"
}
```

配套：

1. **加返回栈**：`var backTo by remember { mutableStateOf("home") }`，进播放页前记住来源，返回时回 `backTo`。
2. **存进度**：现在只存了 `last`（节目 id）。改成存 `lastId` + `lastPosMs`，在 `onMediaItemTransition` 和切后台时写。
3. **更彻底**：每期各存各的进度（`pos_<id>`），"继续收听"用最近一期；以后加"从上次中断处继续"就靠它。

### 顺带要改的

- `PlayerBox.playEpisode(ep, startMs)` 已有 `startMs` 参数，但 `startPlay` 一直传 0。接口是留好的，只是没用。

## BUG-002 拖动进度条卡顿、不跟手

**状态**：✅ 已修（2026-11-23）
**现象**：拖进度条时卡，松手后还会跳一下。

### 根因

| # | 位置 | 问题 |
|---|---|---|
| 1 | `MainActivity.kt:332` | `onValueChange = { onSeek((it * dur).toLong()) }` —— **拖动过程中每一帧都调 `seekTo`**，ExoPlayer 每次 seek 都要重新定位、重新解码，必然卡 |
| 2 | `MainActivity.kt:77` | 每 500ms 轮询 `currentPosition` 写回 `posMs`，拖动时 slider 被这个旧值**往回拽** |
| 3 | 组合 | 拖动 + 高频 seek + 状态回写，Compose 每帧重组，掉帧 |

### 修法

拖动期间只改本地状态，**松手才 seek 一次**：

```kotlin
var dragging by remember { mutableStateOf(false) }
var dragValue by remember { mutableFloatStateOf(0f) }

Slider(
    value = if (dragging) dragValue else (posMs.toFloat() / dur).coerceIn(0f, 1f),
    onValueChange = { dragging = true; dragValue = it },
    onValueChangeFinished = {
        onSeek((dragValue * dur).toLong())
        dragging = false
    }
)
```

配套：

- 轮询那段加 `if (!dragging)`，拖动时不让外部值覆盖。
- seek 完成后等一次 `currentPosition` 回来再放开 `dragging`（避免松手瞬间闪回旧位置）。

## BUG-003 播放页按系统返回直接退出到桌面

**状态**：✅ 已修（2026-11-23）
**现象**：在播放详情页按系统返回键/返回手势，App 直接退到桌面，而不是回首页。

### 根因

Compose 里没有拦截系统返回，`Activity` 被直接 `finish()`。
App 内那个向下的箭头走的是自己的 `onBack`，所以只有点箭头才正常，返回键/手势不归我们管。

### 修法

```kotlin
var backTo by remember { mutableStateOf("home") }

BackHandler(enabled = screen != "home") {
    screen = when (screen) {
        "reader" -> "player"
        "player" -> backTo      // 从列表进的就回列表，从首页进的就回首页
        else     -> "home"
    }
}
```

顺带加了最小的返回栈：进播放页前记 `backTo`，列表进来回列表、首页进来回首页。
（这就是 BUG-001 里"导航没有栈"的临时解法，等修 BUG-001 时统一换成 sealed class。）

**验证**：`adb shell input keyevent KEYCODE_BACK` 后 `topResumedActivity` 仍是 `io.github.jolewis.echoes/.MainActivity`，界面回到首页。

## BUG-004 重启后点播放没反应

**状态**：✅ 已修（2026-11-23）
**现象**：杀掉 App 重开，点迷你播放条的播放键，进度条不动、没声音。

**根因**：重启后只把「上一期」记在 `current` 里用于显示，**从没把它装进播放器**。
MediaController 的队列是空的（`state=NONE`），这时 `play()` 是空操作，不报错也不播。

**修法**：抽了一个 `togglePlay`：队列空且当前有节目时，先 `ensureLoaded(current)` 再播。
`startPlay` 也复用它，避免两处逻辑不一致。

**验证**：冷启动后直接点播放键 → `state=PLAYING`。

## BUG-005 点「下一曲」闪退

**状态**：✅ 已修（2026-11-23）
**现象**：播放页点下一曲，App 直接崩掉。

**根因（两个，都真实存在）**：

1. **`volume must be between 0 and 1`** —— `applyGain` 里把音量钳到 `0.05f..1.4f`，
   但 Media3 的 `setVolume` 只接受 0..1。随机跳到一期**录音偏轻、需要正增益**的节目时，
   `10^(gain/20)` 大于 1 → 直接抛 `IllegalArgumentException`。
   **这个是抓到完整崩溃栈才确认的，不是猜的。**

2. **多段节目续播位置越界** —— `duration_sec` 是全集总时长（马克思 19.36 小时），
   但播放队列第一段只有 16 分钟。`setMediaItems(items, 0, savedPos)` 里 savedPos 可能是一小时，
   远超第一段时长 → `IllegalSeekPositionException`。

**修法**：

- 音量钳到 `0..1`（正增益暂时做不到放大，见 BUG-007）
- 新增 `resolveStart()`：把「全集内绝对位置」换算成「第几段 + 段内偏移」，
  并钳到该段时长以内；外面再包一层 `try/catch`，任何位置异常都退回从头播

**验证**：把马克思的续播位置人为设成 5,000,000 ms（1 小时 23 分），重开 App 播放 →
落到第 **5/29** 段、段内 881 秒，不崩。连点 10 次下一曲无异常。

## BUG-007 正增益无法放大音量（待办）

**状态**：待修
**说明**：现在 `gain_db > 0` 的节目（录音偏轻的少数期）只能停在 1.0 音量，

## BUG-008 后台播放时点图标会重新扫描，像重启

**状态**：✅ 已修（2026-11-23）
**现象**：放着歌回到桌面，再点图标进来，又出现"正在加载 3,000 多期…"，要等 3–5 秒。

**根因**：进程没死（实测 PID 不变，播放服务还活着），是 **Activity 被 MIUI 后台回收了**，
重新进来时 `onCreate` 重建，Compose 状态全丢，`LaunchedEffect(Unit)` 又去扫了 3,218 个 `meta.json`。

**修法**：两层缓存

1. **进程内缓存** `LibraryCache.mem` —— Activity 重建时直接命中，零 I/O
2. **磁盘缓存** `files/library.cache` —— 一行一期（约 3.9 MB），冷启动解析约 200 ms，
   比读 3,218 个独立文件快一个数量级；缓存未命中才全量扫描，扫完顺手写回

启动流程变成：**先出缓存 → 界面立刻可用 → 后台比对有没有新增**（期数变了才换列表并重写缓存）。

**验证**：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 冷启动 | 3–5 秒转圈 | **2 秒内出列表** |
| 后台回前台 | 重新扫，转圈 | **1.2 秒完整渲染，无转圈**，播放不中断（4:22/4:47 接着走） |

**遗留**：每次启动仍会在后台做一次全量比对扫描（不可见，但费电）。
如果以后觉得耗电明显，可以改成"缓存超过 12 小时才校验"或加个手动刷新。

## BUG-009 播放页底部文字被裁掉

**状态**：✅ 已修（2026-11-23）
**现象**：播放详情页最下面那行提示（"适合什么时候听"）被屏幕底部切掉一半。

**根因**：整页是固定高度的 `Column`，封面用 `aspectRatio(1f)` 占满宽度（这个屏幕上约 1000 px），
下面还有标题、摘要、进度条、按钮、定时器五块，加起来超过屏高，最后一行被挤出可视区。
`Spacer(weight(1f))` 也没用——它只会把溢出部分推到屏幕外。

**修法**：

1. 封面高度改成 `min(屏宽 × 0.92, 屏高 × 0.40)`，不再随宽度无限长
2. 整页套 `verticalScroll`，小屏上可以滚动，不会再裁
3. 去掉底部的 `weight` 占位（在可滚动列里没有意义）

## BUG-010 配图从未入库（首版遗漏）

**状态**：✅ 已修（2026-11-23）
**现象**：文字版里的配图，App 里一张都看不到。

**根因**：`build.py` 只创建了 `images/` 空目录，**拷贝那一步从来没写**。
规范里写了 `images/01.jpg` 的结构，实现漏了。

**补数据**：新增 `import_images.py`

- 从 `meta.source.doc` 所在目录（含子目录）收集图片
- 按自然序重命名为 `01.png / 02.jpg …`
- 写回 `meta.assets.images`
- 用 `\\?\` 前缀绕开 Windows 260 字符路径限制（源里有几个超长文件名）

结果：**2,634 期有配图，33,765 张，8.13 GB**。

### 补数据时踩的坑（BUG-011）

**20 期被塞了 599 张无关图片。** 这些期的文稿直接放在 `2016\长篇\` 这种分类目录里，
不是"每期一个文件夹"，脚本把整个分类目录的图都收了进来。
修法：父目录是 `短篇/长篇` 时，只在同名子目录里找图，找不到就留空。
（`fix_images.py`）

### 播放页三模式

| 模式 | 内容 |
|---|---|
| 封面 | 大字封面 + 标题 + 一句话简介 |
| **画面** | 配图横向滑动，可自动轮播（4 秒），点图进全屏，双指缩放 |
| **字幕** | 按 `blocks.json` 的 `start_ms` 逐句跟随，当前句高亮，点句子跳转到该时间 |

- 程序自动滚动期间不算"用户手动滑动"（否则一进页面就自己把跟随关掉）
- 用户手动滑走后暂停跟随 5 秒，并显示「回到当前」胶囊

## BUG-011 配图自动轮播停在半页

**状态**：✅ 已修（2026-11-23）
**现象**：自动轮播时画面滑到一半就停住，像是卡在两页之间。

**根因**：`LaunchedEffect` 的 key 里带了 `pager.currentPage`。
动画一开始，页面索引在过渡中变化，key 变了 → 协程被取消 → 动画中断在半路。
**这是 Compose 里很典型的一类错误：把"动画的副作用"写成了"动画结果的依赖"。**

**修法**：key 只留 `auto, playing, ep.id`，循环里自己推进页码：

```kotlin
LaunchedEffect(auto, playing, ep.id) {
    if (!auto || !playing) return@LaunchedEffect
    while (true) {
        delay(4000)
        pager.animateScrollToPage((pager.currentPage + 1) % ep.images.size)
    }
}
```

**验证**：手动滑动正常（7/7），自动轮播从 1/7 依次走到 3/7 并继续。

## BUG-012 字幕未垂直居中（部分修复）

**状态**：⚠️ 未完全修好
**现象**：当前句没有落在屏幕正中，而是在上三分之一处（约偏上 300 px）。

**试过的三种写法**：

| 方案 | 结果 |
|---|---|
| `contentPadding` 半屏 + `scrollToItem(cur)` | 无明显效果 |
| `scrollToItem` + 读 `layoutInfo` 迭代校正 | 不收敛（`scrollToItem` 后 layoutInfo 滞后一帧） |
| `scrollToItem(cur, scrollOffset = -(vh/2 - 110))` | 改善但仍偏上约 250 px |

**当前状态**：可用（当前句始终在可视区上中部，跟读不费劲），但没达到"正中间"。

**下次的思路**：不再依赖 `scrollToItem` 的偏移语义，改用
`onGloballyPositioned` 记录每句的绝对 Y，或者把每句做成等高块（固定高度）后按索引乘高度定位。
`scrollOffset` 在 LazyColumn 里和 dp/px 的关系容易混，是这次反复没对上的地方。
